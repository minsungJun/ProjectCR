# ProjectCR 설계

3D 룰렛 로그라이크. 라운드마다 정해진 회전 수 안에 돈을 불려 납부금을 내야 다음 라운드로 간다.
지금은 38칸 해골 휠(0~36 + 해골), 숫자 하나·안쪽·바깥 베팅(한 회전에 여러 개), 라운드·자동 납부, 라운드 통과 보상 음료(베팅 묶음 지급 강화)까지 있다. 상점·아이템은 아직 없다.

## 핵심 원칙

- **결과는 로직이 먼저 정하고, 3D는 그 칸에 멈추는 연출만 한다.** 물리로 판정하지 않는다.
  정산은 공의 실제 위치가 아니라 `SpinResult`를 본다.
- 결과는 처음부터 공 여러 개를 담는다(`SpinResult.Balls`). 기본 플레이는 공 1개.
- 정적 설정(ScriptableObject)은 런타임에 고치지 않는다. 회전마다 `SpinConfig`로 복사하고 아이템은 복사본만 고친다.
- 중복 회전·중복 차감·중복 정산은 UI가 아니라 `GameFlowController`가 막는다.

한 회전의 순서와 아이템이 끼어들 자리:

```
베팅 검증 → 확정·차감 → BuildSpinConfig()   ← 회전 전: 공 수, 칸 가중치, 지급 배율, 음료 묶음 배율
                     → SpinResolver.Resolve
                     → ApplyResultOverrides() ← 결과 확정 후: 재추첨, 결과 변환 (지금은 디버그 지정 번호)
                     → presenter.Play(result) ← 모든 공의 연출이 끝날 때까지. 해골이어도 중단하지 않는다
                     → CompleteSpin(id)        ← 전체 결과 평가(해골 먼저) → 정산(배율·보너스) → 기록
                     → 다음 진행(Betting 또는 RoundPayment)
                     → SubmitPayment()         ← 라운드 종료(자동): 납부금 할인이 들어올 자리
                     → ConfirmDrink(i)         ← 보상 확정 → 다음 라운드. 상점이 생기면 이 사이에 넣는다
```

## 해골 칸

38칸 = 0~36 + 해골. 해골은 인덱스 19, 0의 정반대(10과 5 사이)다. 콘셉트 시안과 같은 배치.

- 데이터: `PocketKind.Skull`, 번호 `RouletteDefinition.SkullNumber`(-2), 색 `PocketColor.None`.
  번호 조회(`IndexOfNumber`/`ContainsNumber`)에서 빠지므로 **베팅할 수 없고**, 색이 없어서 색 베팅에도 걸리지 않는다.
  번호(-2)로 홀짝 같은 계산을 하기 전에 반드시 `IsSkull`부터 본다(`PayoutCalculator.Covers`).
- **공 하나라도 해골이면 그 회전의 모든 베팅이 낙첨**이다. 다른 공이 맞혀도 지급 0. 시작 때 뺀 베팅금은 돌려주지 않는다.
- **해골 벌칙(2026-10-09)**: 베팅금을 뺀 뒤 남은 보유 금액을 절반으로 줄인다. 소수점은 반올림(91 → 45.5 → 46, 1 → 1).
  해골 공이 여럿이어도 회전당 한 번. 비율은 `GameBalance.skullBalanceKeep`(0.5), 계산은 `GameBalance.SkullKeptBalance`, 적용은 `GameFlowController.CompleteSpin`.
  빠진 돈은 `SettlementResult.SkullPenalty`에 남고 `Net`(손익)에 들어간다. 결과 문구: "해골 낙첨 · 지급 0 (−베팅액) · 보유 절반 −벌칙".
  결과 이유는 `SpinOutcome.SkullBust`로 일반 낙첨(`Lose`)과 구분한다.
- 해골은 **상태를 바꾸지 않는다.** 정상 회전 종료라 회전 1회를 쓰고 일반 회전과 같이 Betting/RoundPayment로 간다.
  GameOver는 납부 실패에서만 나온다. 마지막 회전 해골도 그대로 납부 단계로 간다.
- 공이 여러 개면 모든 공의 연출이 끝난 뒤 한 번만 평가·정산한다. 공별로 먼저 지급하는 경로는 없다.
- 해골 판정이 정산 맨 앞이라 지급 배율·당첨 보너스·낙첨 환급은 해골 회전에 적용되지 않는다.
  "해골에도 환급" 같은 효과는 나중에 SkullBust 전용 단계로 따로 붙인다. 해골을 없애는 재추첨·결과 변환은 요구가 생기기 전까지 넣지 않는다.
- 연속 낙첨 기록(`ConsecutiveLosses`)에는 해골 낙첨도 들어간다.
- UI: 해골 베팅 칸은 없다. 번호판 아래 고정 문구 "해골: 모든 베팅 낙첨 + 보유 금액 절반".
  결과는 일반 결과 패널에 `결과 ☠ 해골 — 해골 낙첨 · 지급 0 (−베팅액)`, 최근 기록에 ☠. 패배 화면·재시작·즉사 연출과는 연결하지 않는다.
- 공 1개 기준 해골 확률 1/38. 숫자 베팅 36배를 그대로 두면 기대 환수율이 97.3% → 94.7%로 내려간다.
- 2026-10-09부터 해골은 가중치 목록에 들어가지 않는다. 공마다 해골 여부를 원본 칸 구성 비율(1/38)로 먼저 정하고, 아니면 0~36만 가중치로 뽑는다.
  그래서 확률 음료로 숫자를 올려도 해골 위험은 그대로다(공이 늘면 해골이 하나라도 나올 위험은 커지고, 음료가 보정하지 않는다).

## 공이 목표 칸에 들어가는 원리

공 위치를 **WheelPivot 로컬 좌표(휠에 대한 상대 각도 φ)** 로 계산한다.

```
u    = clamp01(elapsed / duration)
φ(u) = φ0 + Δ·angleCurve(u),   Δ = −(360·N + ((φ0 − 목표각) mod 360))
```

φ(1)이 목표 칸 각도와 360° 단위로 같으므로 휠 속도·프레임 속도와 무관하게 착지한다.
u ≥ 1이면 커브 값과 상관없이 정확히 끝 각도를 쓴다. 착지하면 공을 PocketAnchor 자식으로 붙인다.
세계 기준 공 속도 = 휠 속도 + φ' 이라 초반엔 휠 반대로 돌고, φ'이 0이 되면 휠에 실려 멈춘다.

각도 규약: 위에서 볼 때 시계 방향 +, 로컬 +Z가 0° (`Quaternion.Euler(0, a, 0) * forward`).

## 휠 정지: 결과 칸을 6시에 세운다

회전을 시작할 때 휠의 움직임 전체를 미리 계획한다(`WheelSpinPlan`): 가속(`launchDuration`) → 일정 속도 → 감속해 정지.
정지 시각은 마지막 공이 안착한 뒤 `wheelStopDelay`(기본 1초), 감속 구간은 `wheelStopDecelDuration`(기본 3초).
정지 각도가 "휠 각도 + 결과 칸의 휠 로컬 각도 = `restAngle`"(기본 180° = 6시, 카메라 쪽)이 되도록
일정 속도만 평소(`spinWheelSpeed`) 근처에서 조정한다(기본 설정에서 대략 ±35%, 최소 절반). 공 1개 이상이면 공 1번의 칸을 세운다.

- 공은 휠 로컬로 계산하므로 휠을 어떻게 움직여도 들어가는 칸은 그대로다.
- 각도는 경과 시간의 함수라 프레임 속도와 무관하고, 끝나면 정확히 목표 각도다.
- 결과 표시(정산)는 휠이 멈춘 뒤에 한다(`SpinStage.WheelStop`). 휠은 다음 회전까지 멈춰 있고, 첫 회전 전에만 천천히 돈다.
- 연출 시점 카메라는 휠 중심에서 오른쪽으로 비켜 있어 6시 칸이 화면에서 아주 조금 왼쪽 아래로 보인다. 탑다운 시점에서는 정확히 아래다.

## 3D 테이블 베팅 (2026-10-08)

화면은 테이블 전체를 앞(+Z)에서 내려다본다: 왼쪽 룰렛, 오른쪽 베팅판, 앞쪽 칩 트레이와 잔액 표시. 2D 번호판은 없앴다.

- **베팅판 좌표**(`TableBetBoard` + 순수 계산 `BoardLayout`): 칸 단위 좌표가 2D 판·`InsideBets`와 같다.
  빌더가 칸 메시 `CRT_Bet_Color_01~36`(열 0.0967m, 행 0.13m)과 격자 메시 `CRT_Bet_Grid_Merged_Zero`에서
  원점·축·0번 칸·열 베팅·더즌 줄·2배 줄 경계를 잰다. 빨강 마름모가 x 5.00에 오는지 로그로 확인한다.
- **고르는 규칙**(`BoardLayout.TryGetTarget`): 칸 경계·모서리 점에서 가로 0.22칸·세로 0.17칸 안이면 안쪽 베팅, 아니면 칸.
  칩은 `UnitsOf`(칸 가운데 또는 경계 점)에 놓는다. 모든 대상(숫자 37 + 안쪽 108 + 바깥 12)이 왕복 일치(EditMode, 실제 카메라 광선으로도 157/157).
- **입력**(`TableBetInput`, Input System): 판 왼쪽 클릭 = 칩 놓기, 오른쪽 클릭 = 빼기, 트레이 칩 클릭 = 칩 금액(1~5000).
  트레이는 칸마다 BoxCollider(`ChipTraySlot`), 판은 콜라이더 없이 평면 광선 계산. HUD의 `blocks-input` 요소 위 클릭은 무시.
- **표시**(`TableChipView`): 판 위 칩 더미(모델 칩 견본 `CHIP_*`를 `chipScale` 1.4배로, 큰 칩부터 최대 10개), 고른 트레이 칩 들어 올리기,
  가리킨 자리 금색 점, 잔액 표시 화면 글자(TextMesh).
  - 칩 더미마다 위에 그 자리 합계(TextMesh + 그림자)를 띄운다. 카메라를 보고, 화면에서 칩 위에 오도록 카메라 위 방향으로 `amountLabelLift`만큼 띄운다(2026-10-09).
  - 잔액 표시 = 보유 − 판에 놓은 칩 합계(1,000 보유, 400 베팅 → 600). 회전이 시작되면 합계가 지갑에서 빠지므로 그때부터는 보유 그대로.
    HUD 위 상태 바의 "보유"는 실제 지갑 금액이다.
- **HUD**: 위 상태 바·결과, 아래 띠(칩·가리킨 자리와 배수·베팅 목록·최고 지급·오류·취소·회전).
- **카메라 이동**(`CameraRig`, Main Camera에 붙음): 씬의 빈 오브젝트 `CameraPostion_BettingBoard`(베팅) ↔ `CameraPostion_Roulette`(회전) 자리로
  0.9초 동안 부드럽게 옮긴다(위치 Lerp·회전 Slerp, EaseInOut). 회전은 베팅 확정·차감 직후 카메라가 룰렛 자리에 **도착한 뒤** 시작한다.
  결과가 나오면 1.5초 보여 주고 베팅판으로 돌아가고, 라운드가 끝났으면 룰렛에 머물러 납부 판정·음료 선택을 하고 확정 뒤 돌아간다.

## 규칙(임시값)

- **한 회전에 여러 베팅**을 건다. 번호판 왼쪽 클릭 = 칩 금액만큼 놓기(같은 자리면 쌓임), 오른쪽 클릭 = 그 자리 베팅 빼기,
  "마지막 칩 취소"(칩 단위 되돌리기), "전체 취소".
  - 놓을 때마다 대상·금액(최소 베팅 이상)·합계 ≤ 보유를 검사한다. 돈은 회전 시작 때 **합계를 한 번** 뺀다.
  - **회전이 끝나면 판의 칩을 모두 없앤다**(2026-10-08, 사용자 요청). 다음 회전은 빈 판에서 다시 건다. 돈은 바뀌지 않는다(베팅금은 시작 때 빠졌고 당첨금은 원금 포함).
  - 정산은 베팅마다·공마다 판정해 모두 더한다(`SettlementResult.Bets`). 해골이면 전부 낙첨.
  - 결과 `Win`은 "지급이 하나라도 있음"이다. 빨강·검정 동시 베팅처럼 손익이 0 이하일 수 있다(`Net`). 연속 낙첨은 지급 0일 때만 센다.
  - 미리보기는 "공 하나 기준 최고 지급"(어느 숫자가 나오면 가장 많이 받는지)을 보여 준다.
- 원금 포함 총 지급 배수(`GameBalance`, 회전마다 `SpinConfig`로 복사):

  | 묶음(`PayoutClass`) | 베팅 | 칸 수 | 배수 |
  |---|---|---|---|
  | Straight | 숫자 하나(0 포함) | 1 | 36 |
  | Split | 붙은 두 숫자(가로 33, 세로 24, 0-1·0-2·0-3) | 2 | 18 |
  | Street | 한 줄 세 숫자 12개 + 트리오 0·1·2, 0·2·3 | 3 | 12 |
  | Corner | 네 숫자 모서리 22개 + 퍼스트 포 0·1·2·3 | 4 | 9 |
  | SixLine | 붙은 두 줄 11개 | 6 | 6 |
  | DozenColumn | 1–12 / 13–24 / 25–36, 1열(1·4·…·34) / 2열 / 3열(3·6·…·36) | 12 | 3 |
  | EvenMoney | 빨강·검정, 홀·짝, 1–18·19–36 | 18 | 2 |

  배수 × 칸 수 = 36이라 38칸 휠에서는 어떤 베팅이든 기대 환수율이 36/38(94.7%)로 같다.
- 안쪽 베팅은 번호판에서 실제로 붙어 있는 조합만 걸 수 있다(`InsideBets.IsValid`, 아니면 `BetError.InvalidTarget`).
- 번호판 UI: 칸 경계에 클릭 점을 둔다. 두 칸 사이 = 스플릿, 네 칸 모서리 = 코너, 줄 아랫변 = 스트리트, 두 줄 사이 아랫변 = 식스 라인,
  0번 칸과 첫 열 경계 = 0이 든 조합. 누르는 영역 16px, 보이는 점 5px. 안쪽·바깥 베팅 자리에 마우스를 올리면 포함되는 숫자 칸 테두리가 금색이 되고, 칩이 놓인 자리에는 금액 배지가 붙는다.
  칸 간격 상수(`RouletteHud.ColumnPitch` 등)는 USS의 `.cell` 크기와 맞춰야 한다.
- **0이 나오면 바깥 베팅은 모두 진다**(표준 규칙. 절반 환급 같은 라 파르타주 규칙은 쓰지 않는다). 해골은 어떤 베팅에도 포함되지 않는다.
- 낙첨 지급 0.
- 공 여러 개: 공별 독립 추첨, 차감은 회전당 1회, 공별 지급 합산. 같은 칸이면 칸 안에서 안쪽·바깥쪽으로 비켜 놓고, 공마다 0.35초씩 늦게 들어온다.
- 초기 100, 최소 베팅 1, 라운드당 5회전, 납부금은 아래 "라운드 납부와 음료" 참고.
- 회전이 남았어도 최소 베팅을 못 내면 남은 회전을 버리고 납부 판정으로 간다. 바로 게임 오버로 보내지 않는 건 납부금 할인 같은 효과가 생길 수 있어서다.

## 라운드 납부와 음료 (2026-10-09)

흐름: 라운드 시작 → 베팅·회전 반복 → 회전을 다 씀(또는 최소 베팅 불가) → 납부 판정 → 납부금 차감 → 음료 선택 → 다음 라운드. 납부는 매 라운드.

- **납부금**: `GameBalance` 라운드 항목(회전 수·첫 납부금·증가율·올림 단위). due(n) = 올림(120 × 2.5^(n−1), 5).
  120 / 300 / 750 / 1,875 / 4,690 / 11,720 / 29,300 / 73,245. 앞 라운드 값에 곱하지 않고 매번 공식으로 계산한다.
  2026-10-09 사용자 요청으로 증가율을 1.5 → 2.5("더 강한 압박")로 올렸다(×2 안도 있었다: 120 / 240 / 480 / … / 15,360).
  라운드별 목록 입력은 없다(필요해지면 "공식/목록" 중 하나를 고르는 방식으로). 끝없는 진행이고, 약 26라운드부터 납부금이 돈 상한에 걸린다.
- **납부 판정**: 버튼 없이 자동이다. 마지막 회전 정산이 끝나고 결과를 `CameraRig.returnDelay`(1.5초) 보여 준 뒤 `SubmitPayment`를 한 번 부른다.
  - RoundPayment 상태에서만 동작하고 즉시 상태가 바뀐다. `RoundManager.Pay`도 라운드당 한 번만 뺀다. 이중 차감 없음.
  - 성공: 납부금만 빼고 나머지는 이월 → DrinkSelection. 실패: 아무것도 빼지 않고 GameOver(음료 없음).
  - 판정은 금액만 본다. 돈이 없어 회전을 버린 경우도 같은 판정을 거친다.
- **음료 묶음**(`DrinkGroup`): 컬럼(1~3열) / 더즌 / 홀짝 / 색상 / 높고 낮음 / 숫자(숫자 하나 0 포함·스플릿·스트리트·코너·식스 라인).
  결과 번호가 아니라 **베팅 종류**로 정한다. 빨간 숫자에 건 숫자 베팅은 숫자 묶음일 뿐 색상 음료가 붙지 않는다. 해골은 베팅할 수 없어 어느 묶음에도 없다.
- **효과**: 묶음 배율 = 한 잔 배율(1.5)^잔 수. 곱으로 쌓이고 이번 게임 끝까지 간다. 잔 수 상한 없음.
  최종 배수 = 기본 배수 × 묶음 배율(예: 빨강 2 → 3 → 4.5, 1열 3 → 4.5, 숫자 36 → 54). 기본 배수와 잔 수에서 매번 다시 계산한다.
  배율은 10^15(`DrinkRunState.MultiplierCap`)에서 멈춘다. 그때는 최소 베팅으로도 지급이 돈 상한이라 결과가 같고 decimal이 넘치지 않는다.
- **정산**: 베팅금 × 최종 배수를 모든 베팅·공에 대해 decimal로 정확히 더하고, **회전 합계에서 한 번만 버림**한다(예: 빨강 1 + 1열 1, 둘 다 ×4.5 → 9. 베팅마다 버리면 8).
  베팅별 금액(`BetPayout.Amount`)은 표시용 버림이고 정확한 값은 `ExactAmount`. 베팅금 차감·검증에는 음료가 관여하지 않는다.
  **해골 판정이 먼저라 음료가 있어도 해골 회전은 지급 0.**
- **보상**: 6종 중 서로 다른 4종을 보여 주고(이미 마신 음료도 나온다) 하나를 고른다. 다시 뽑기·건너뛰기 없음.
  후보는 창을 열 때 한 번 만들고 고를 때까지 그대로다. 추첨 난수는 결과 추첨과 따로(`Seed ^ 0x5EED5EED`)라 보상을 뽑아도 회전 결과 순서가 바뀌지 않고, 같은 시드면 후보도 같다.
  `ConfirmDrink`는 DrinkSelection 상태에서만 동작해 두 번 눌러도 한 잔만 들어간다. 확정하면 라운드 +1, 회전 5로 채움, 판 비움. 돈과 음료는 그대로.
  새 라운드에도 걸 돈이 없으면 기존 규칙대로 바로 납부 판정(대개 GameOver).
- **음료 창**(`drink-panel`): 화면을 어둡게 덮고 `blocks-input`으로 테이블 입력을 막는다. 호두나무 판·황동 테두리·펠트 카드.
  위에 "라운드 N 통과 · 납부 · 남은 돈", 제목 "음료 하나를 선택하세요", 카드 4장(그림, 이름, 묶음, 효과, 지금 잔 수·배율, 마시면 잔 수·배율, 대표 베팅 배수 변화), [선택 확정].
  카드를 누르면 강조만 되고 확정 버튼이 켜진다. 그림이 없으면 강조색 병을 그린다. 좁은 화면에서는 카드가 2×2로 줄바꿈한다.
- **게임 중 표시**: 음료 목록을 늘 띄우지 않는다. 판 위에 마우스를 올리면 "빨강 · 2배 → 3배 (색상 음료 ×1.5)"처럼 기본·강화 배수를 보여 주고, 최고 지급 미리보기도 강화 배수로 계산한다.
- **새 게임**: `GameFlowController`를 새로 만들어 돈·라운드·음료가 모두 처음으로 돌아간다. 저장 기능은 없다.
- 디버그: `RouletteGame.debugStartDrinkStacks`(새 게임 시작 잔 수, 순서 컬럼·더즌·홀짝·색상·높고 낮음·숫자).

- **가중치**: 일반 칸 가중치 = 기본 × (1 + 그 칸에 걸린 모든 효과의 잔 수 × 계수 합). 같은 대상은 잔 수가 더해지고, 겹치는 대상끼리도 더한다
  (7번 = 빨강 2잔 +20% + 1–18 1잔 +10% + 7번 1잔 +30% → ×1.6). 곱하지 않아서 적용 순서와 상관없다. 매 회전 원본 가중치와 잔 수에서 다시 계산한다.
  0은 숫자 하나 대상으로만 오르고, 색상·홀짝·구간·더즌·컬럼·숫자 묶음에는 들지 않는다. 해골은 대상이 될 수 없다. 잔 수 상한은 없다.
- **확률**: P(해골) = 1/38 고정, P(일반 칸 i) = (37/38) × w_i / Σw. 강화가 없으면 모든 칸 1/38. 추첨(`SpinResolver`)·카드·마우스 올림 안내가 같은 식(`PocketWeightCalculator`)을 쓴다.
- **회전**: 회전 시작 때 만든 `SpinConfig`에 가중치가 들어가고, 그 회전의 모든 공(추가 공 포함)이 같은 설정으로 뽑는다. 회전 중 상태가 바뀌어도 영향 없다.
  이미 나온 결과를 바꾸지 않고, 베팅과 상관없이 적용한다(건 칸을 따로 유리하게 하지 않는다). 해골 방패는 아직 없다(생기면 같은 설정으로 다시 뽑는다).

### 밸런스: 지급 강화 + 확률 강화

빨강(안전한 베팅)의 기대 환수율 = 등장 확률 × 2 × 지급 배율. 100%를 넘으면 걸수록 이득이다(`BalanceSimulationTests`, 빨강 확률 +37%/잔):

| 지급 음료 \ 빨강 확률 음료 | 0잔 | 1잔 | 3잔 | 5잔 | 10잔 | 20잔 |
|---|---|---|---|---|---|---|
| 0잔 | 94.7% | 110.0% | 129.8% | 142.1% | 159.0% | 173.0% |
| 1잔 (×1.5) | 142.1% | 165.0% | 194.7% | 213.2% | 238.5% | 259.5% |
| 2잔 (×2.25) | 213.2% | 247.5% | 292.1% | 319.7% | 357.8% | 389.2% |
| 3잔 (×3.375) | 319.7% | 371.2% | 438.1% | 479.6% | 536.7% | 583.9% |

- 확률 음료 5잔 ≈ 지급 음료 1잔(142%). 확률만으로는 상한(194.7%)에 가까워질수록 덜 오른다.
- 둘을 겹치면 곱으로 커진다(지급 2잔 + 확률 3잔 ≈ 292%). 해골(1/38, 보유 절반)과 납부금 ×2.5가 유일한 견제다.
- 생존 시뮬레이션(×2.5 납부금, 해골 절반, 지급·확률 1:1): 빨강 목표 베팅 + 음료 R2 8.4% · R3 1.8%, 더즌 1/3 + 음료 R2 3.2% · R12 0.3%.
  계수를 올려도(+10% → +37%) 생존은 거의 그대로다. 원하는 대상(예: 빨강)이 후보에 나오는 일이 드물어서다(색상 확률 음료가 나와도 절반은 검정).
  후보에 두 계열이 섞여 원하는 지급 음료가 덜 나오므로, 지급 음료만 있던 때(R2 9.7%)보다 조금 낮다.
- 조정 후보: 확률 계수(+10%~+30%), 계열 비중(`payoutShare/probabilityShare`), 중첩 상한(지금은 없음).
